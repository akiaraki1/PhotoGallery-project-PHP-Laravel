# Фотогалерея

Учебный веб-проект на Laravel: пользователи регистрируются, подтверждают почту, ведут профиль со своим аватаром и добавляют фотографии в одну из шести тематических категорий. Остальные пользователи просматривают галереи по категориям с постраничным выводом.

## Стек технологий

- **PHP 8.3+**, **Laravel 13**
- **MySQL** — хранение данных (пользователи, фотографии)
- **Laravel Breeze** (Blade-стек) — регистрация, вход, подтверждение почты, сброс пароля, обновление профиля
- **Intervention Image** (`intervention/image`, `intervention/image-laravel`) — обработка загружаемых изображений (обрезка под квадрат)
- **Vite + Tailwind CSS + Alpine.js** — сборка фронтенда
- **Laravel Pail / Pint / PHPUnit** — для разработки и тестирования (dev-зависимости)

## Функциональность

- Регистрация и вход по email/паролю, подтверждение почты (email verification)
- Восстановление пароля по ссылке, которая приходит на почту
- Личный профиль: смена имени, email, пароля, загрузка/смена аватара (обрезается до 300×300)
- Главная страница галереи с 6 категориями: **Природа, Города, Архитектура, Портреты, Путешествия, Животные**
- Внутри категории — список фотографий с пагинацией (по 6 на страницу)
- Добавление фото в категорию: заголовок, описание, изображение (jpeg/jpg/png/webp, до 5 МБ, от 300×300 до 500×500 px, обрезается под 400×400)
- Редактирование и удаление своих фотографий (проверяется, что пост принадлежит текущему пользователю)

## Структура проекта (ключевые места)

- `app/Http/Controllers/PhotoGalleryController.php` — вывод категорий, CRUD фотографий
- `app/Http/Controllers/ProfileController.php` — профиль и аватар
- `app/Services/ImageManager.php` — обрезка, сохранение и удаление изображений на диске `public`
- `app/Models/PhotoGallery.php`, `app/Models/User.php` — модели
- `database/migrations/` — таблицы `users` (+ поле `avatar_image`), `photo_galleries`
- `resources/views/` — Blade-шаблоны (galerея, профиль, формы входа/регистрации от Breeze)
- `routes/web.php`, `routes/auth.php` — маршруты приложения и аутентификации

## Что нужно подключить, чтобы проект заработал

### 1. Системные требования
- PHP ≥ 8.3 с расширениями: **GD** или **Imagick** (нужно хотя бы одно — используется для обработки изображений), `pdo_mysql`, `mbstring`, `fileinfo`
- Composer
- Node.js + npm (для сборки стилей/скриптов через Vite)
- Сервер MySQL (локально или удалённо)

### 2. Установка
```bash
composer install
npm install

cp .env.example .env
php artisan key:generate
```

### 3. Настройка `.env`
После копирования `.env.example` обязательно заполнить:

**База данных** — создать пустую БД в MySQL и указать доступ:
```env
DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=photo_gallery
DB_USERNAME=root
DB_PASSWORD=
```

**Адрес приложения** — должен совпадать с тем, по которому реально открываете сайт:
```env
APP_URL=http://127.0.0.1:8000
```

**Почта (для писем подтверждения и сброса пароля)**. Для локальной разработки проще всего оставить:
```env
MAIL_MAILER=log
```
— письма будут падать в `storage/logs/laravel.log`. Чтобы письма реально уходили на ящик пользователя, нужен SMTP, например через mail.ru:
```env
MAIL_MAILER=smtp
MAIL_SCHEME=smtps
MAIL_HOST=smtp.mail.ru
MAIL_PORT=465
MAIL_USERNAME=ваша_почта@mail.ru
MAIL_PASSWORD=пароль_для_внешних_приложений
MAIL_FROM_ADDRESS="ваша_почта@mail.ru"
MAIL_FROM_NAME="${APP_NAME}"
```
Пароль от самого ящика тут не подойдёт — в настройках безопасности почты нужно создать отдельный «пароль для внешних приложений» (с правом только на отправку, SMTP).

**Обработка изображений** — выбрать установленное расширение:
```env
IMAGE_DRIVER=gd
```
(или `imagick`, если оно установлено на сервере).

### 4. Миграции и хранилище файлов
```bash
php artisan migrate
php artisan storage:link
```
Вторая команда обязательна — без неё загруженные аватары и фото категорий не будут отдаваться по `/storage/...` и изображения не отобразятся.

### 5. Сборка фронтенда и запуск
```bash
npm run build      # разовая сборка стилей/скриптов
# или npm run dev   # для разработки с автопересборкой

php artisan serve
```
После этого сайт будет доступен по адресу, указанному в `APP_URL`.

## Важно про безопасность

- Файл `.env` не должен попадать в git/GitHub — в нём хранятся пароль от базы данных и пароль приложения от почты.
- Если какой-либо реальный пароль из `.env` (например, пароль для внешних приложений mail.ru) случайно оказался виден третьим лицам — его стоит отозвать и создать новый в настройках безопасности почты.
